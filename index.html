Follow data through the chip

  1. Choose a case and select Play. Overview arrows show recorded transfers for the current cycle. Modules show values at the selected time.
  2. Open region A to see all 128 × 128 cells. Use the mouse wheel to zoom, drag to pan, or enter row and column coordinates. Double-click a cell to inspect its SRAM, XNOR, MUX, and full-adder connections.
  3. In a cell, select a wire to inspect its value. Use “+” to add it to the waveform pane. “Next node change” advances to the next recorded change; “Slow propagation” shows gate delays. Regions B–F expand into function blocks, instances, and gates. Their wires and port tables use the same waveform pane.
  4. Add selected nodes to the waveform pane. Buses initially show integers. Expand a bus to see the logic level of each bit.
  5. Drag the time cursor forward or backward. Zoom in to inspect gate propagation or zoom out to see the complete task.
  6. Use Key steps to skip long waits. Waveforms, modules, and explanations share one time cursor.

Colors: In the array, blue indicates valid computation and amber indicates a WL write. Light gray cells remain powered but do not supply the current result; their nodes can still switch. Dark hatching and OFF indicate bank power loss. Yellow X indicates unknown storage in a powered cell. Shallow sleep has a separate label and retains weights.

How to interpret the diagrams

Recorded events: Values, handshakes, and transition times come from the Python gate-network simulation. The overview organizes these records into a readable data flow.

Digital levels: 0 / 1 / X / Z are not continuous voltages. The model does not simulate analog edges, noise, or analog metastability. Values are unavailable while bank power is off.

Circuit scope: Cells, buffers, and registers use the known connections. Peripheral circuits are design models, and internal gate delays are assumptions. This viewer does not establish physical maximum frequency, power, or layout timing closure.

Both the bank-to-D and external result interfaces are 64 bits. Input payloads share a 32-bit logical port: weights and inputs use its low 16 bits, and Sg uses all 32 bits. Result width does not determine the physical input-pin implementation.

A task can use W ≠ A, but all selected groups share W/A. Only one task runs at a time. External logic arranges pixels and channels for Pointwise operations.
